本文件记录访谈确认的产品决定与最终技术建议。按用户要求，实施步骤、影响范围、验证与交付条件已整理到 [最终实施计划](implementation-plan.md)。

## 已确认的产品决定

1. 应用名称为 **MiniWatts Pro**。
2. 首版包含实时充电剩余时间预测、单次充电复盘、历史充电比较和报告导出。
3. 所有分析与报告在设备本地完成，由用户主动导出分享。
4. 作为独立应用，与 MiniWatts 共存，需要独立的应用、小组件和 App Group 标识。
5. 充电目标可设置在 50%–100%，默认 100%，提供 80% / 90% / 100% 快捷选择；仅用于分析预测，不控制系统充电上限。
6. 导出 PDF 与 CSV，均支持单次充电及所选时间范围。
7. 历史记录默认全部保留，用户手动清理；需提供存储占用查看及按时间清理。
8. 应用标识为 `io.github.ccatq.MiniWattsPro`，小组件标识为 `io.github.ccatq.MiniWattsPro.Widget`，App Group 为 `group.io.github.ccatq.MiniWattsPro`。
9. 首版从新记录开始，不包含旧版历史导入。
10. 剩余时间结合本次电量上升趋势与同类历史的分段耗时；数据不足时显示粗略估算或积累数据状态，暂停充电及采样中断时停止有效倒计时，注明估算依据，不承诺未经实测的固定误差。
11. 历史按相同电量区间及有线/无线比较，支持 7 / 30 / 90 天、全部和自定义日期筛选；分析用时、平均与峰值功率、能量、电芯占比、温度、系统热压力及数据覆盖率。
12. 缺测指标显示不可用；低覆盖记录保留但不参与速度排名。热压力不直接作为降速原因，适配器名称不作为可靠的充电器身份。
13. 完整保留每 5 秒记录的样本，不再自动隔点抽稀；按会话保存，以避免每次重写全部历史。CSV 导出的是实际记录的样本，不是原始 1 秒探测数据。
14. 将“历史”升级为“分析”，内含总览和历史记录；电量页显示实时预测，详情导出单次报告，分析总览导出区间报告。
15. 单次 PDF 包含摘要、功率/电量/温度曲线及覆盖说明；区间 PDF 包含汇总、可比区间比较及会话摘要表。CSV 分为会话摘要和实际记录样本两类表；注明设备型号、系统与应用版本、目标电量、单位、时区与缺失数据，报告语言跟随应用。
16. 支持单条、按日期范围及全部删除；操作前显示记录数量并确认，只删除已结束会话，保留正在记录的充电。
17. 所有编译使用 GitHub Actions；本地不调用 Swift 或 Xcode 编译。自动化测试也在 Actions 执行，本地仅进行源码、配置、文档和脚本的非编译检查。

## 现有实现依据

- `MiniWatts/Core/Model/ChargeSession.swift`：历史包含输入/电池功率、电量、电池/最高传感器温度、系统热压力，以及会话级能量、峰值、有线/无线、适配器和路径电阻信息。
- `MiniWatts/Core/PowerMonitor.swift`：现有电量变化率用于估算功率，并没有应用自己的充电剩余时间模型。
- `MiniWatts/Core/Model/PowerSnapshot.swift`：剩余时间目前来自可缺失的系统字段。
- 历史默认每 5 秒记点，每次最多 1,500 点，超出后隔点抽稀；磁盘最多保留 60 次会话。
- 普通后台会暂停采样，浮窗运行时继续采样；超过 10 秒的间隔不计入能量积分。无法从旧记录准确还原后台的插拔和暂停充电事件。
- 无线充电通常缺少输入侧电流，不能由额定功率补出实测输入能量。
- 旧历史没有充电目标、逐点充电状态、观测缺口标记、设备型号或预测误差记录；旧版还可能用 0 表示缺失功率。
- 目前没有正式报告、CSV、PDF或系统分享能力，只有原始数据文本复制。
- 现有 `docs/` 原本只有截图和图标，没有功能规范；`CLAUDE.md` 是工程笔记，术语见根目录 `CONTEXT.md`。

## 计算与交互规则

- 预测基于电量变化，不使用充电器额定功率或用户填写的电池容量伪装实测时间。目标已达到时显示“已达到目标”；未连接、充电暂停、电量不可读或观测中断时不显示有效倒计时。
- 历史按 5% 电量区间建立分段耗时，仅使用连续观测且电量上升的完整区间；有线/无线分别建模。每段至少有 3 个合格历史值时使用中位耗时，其余段仅在本次趋势可用时作粗略外推；部分预测依赖外推时标明局限。
- 本次趋势至少观察到两次电量上升，使用近期完整电量变化的耗时。超过 10 秒的观测缺口、状态切换、电量下降或无电量读数打断连续趋势，不把背景空洞插值成实测。
- 历史速度比较选择同一电量区间，默认 20%–80%，可调整；记录须完整覆盖所选区间，且该区间观测覆盖率至少 90%。覆盖不足或没有完整边界的记录仍可复盘，但不排名；合格记录不足时显示样本不足。
- 输入/电池平均功率分别用其能量除以对应有效观测时长；区间电芯占比用合格会话的成对能量总和相除，不平均百分比。温度平均值按有效观测时长加权；没有读数的指标保持缺失，不能用 0 或上次值代替。
- 数据覆盖率是已观测时长占记录时长的比例，分别显示整体观测、输入、电池等覆盖情况；不能把覆盖率理解为传感器准确率。日期筛选按会话开始时间纳入完整会话，报告写明这个规则。
- 图表在缺失读数及观测缺口处断开；保留的完整样本供导出和分析，屏幕图表可按显示宽度抽点但不能改变持久化数据和分析结果。
- PDF 与 CSV 从同一份不可变的数据快照生成，注明导出时间；大范围导出显示进度并可取消。空范围禁用导出；失败显示原因和重试入口；通过系统分享面板保存或分享，取消分享保留历史。
- 单次 PDF 为完整复盘；区间 PDF 提供汇总、可比区间比较及分页会话表，不自动附上每次会话的完整曲线。CSV 同时提供摘要与样本表；采样表标明样本时间、可缺失的读数、充电状态及观测断点。
- 清理仅作用于已结束记录，先展示将删除的数量；删除后刷新索引、分析与存储占用，进行中的记录及采样不受影响。
- 保持 iOS 17 部署目标、无第三方依赖、系统明暗外观及中英文文案；首版不把预测扩展到小组件、实时活动或浮窗。
- 发布显示名及产物统一为 MiniWatts Pro，发布仓库链接改为 `Ccat-Q/MiniWatts-Pro`；保留上游归属和许可证。内部源目录/工程/方案名称可以保留，避免仅为展示改名大幅移动文件。

## 存储组织

- 使用带数据格式版本的会话文件，以及不包含采样数组的摘要索引；总览和预测使用摘要，详情与导出按需读取样本。相比既有整份 JSON，文件组织略复杂，但长期历史不会在每次充电保存和启动时全量编解码。
- 新样本记录可缺失的真实电量、充电状态、观测断点和目标上下文；会话保存设备型号与系统版本，避免把未来备份中的不同设备直接混为可比历史。
- 保存顺序为先原子保存会话，再更新可重建的摘要索引；损坏的单个会话隔离并提示，不清空其他历史。存储失败必须提示，不能静默丢失数据。
- 首版不迁移旧应用历史；强退恢复时把未结束记录结束于最后实际观测，标记为中断记录，不能假装完整充电或续接未观测时段。

## 验收标准

- 应用与旧版可共存，显示名、主应用/小组件/App Group 标识、发布源一致。
- 默认目标 100%，更改目标后预测即时更新；冷启动、历史不足、暂停、缺电量、观测缺口和达到目标具有独立状态。
- 相同电量区间比较不混入不完整或低覆盖记录；无线缺输入不显示虚构输入能量、电芯占比或差额。
- 超过 60 次历史或超过 1,500 个采样点不会自动丢弃；按需读取详情，后台保存避免阻塞每秒 UI 更新。
- 单次及区间 PDF 可阅读、分页正常，CSV 保留空值、单位、时间与样本上下文；两种格式的汇总与页面一致。
- 测试覆盖预测边界、历史分段、缺口、汇总加权、存储恢复/失败/清理和 CSV 转义；验证本地化目录、plist、脚本及工程配置。系统分享和真机传感器仍需设备验证，不能仅凭构建成功宣称这些检查已通过。
- 所有编译和自动化测试在 GitHub Actions 执行，不进行本地 Swift/Xcode 编译；上述 iOS 编译由 Actions 的 macOS/Xcode runner 完成，系统分享与传感器准确性仍需设备验证。
