# MiniWatts Pro 最终实施计划

状态：用户已确认按此计划实施。以下规则为实施与验收依据；构建和测试通过情况以最终 GitHub Actions 运行结果为准。

功能规范见 [analysis-design.md](analysis-design.md)，领域术语见 [CONTEXT.md](../CONTEXT.md)。所有编译和自动化测试使用 GitHub Actions，本地只做非编译的源码、配置、文档及脚本检查。

## 目标与范围

将现有应用发展为独立安装的 **MiniWatts Pro**：实时预测到用户设定电量的剩余时间，复盘单次充电，公平比较历史记录，并在设备本地生成 PDF 和 CSV 报告。

保持 iOS 17 部署目标、无第三方依赖、系统明暗外观及中英文支持。所有分析离线运行，报告仅由用户主动分享。首版从新记录开始；充电目标仅用于预测，不控制系统充电上限。首版预测入口在电量页，小组件、实时活动及浮窗维持已有读数能力。

## 实施顺序与依赖

### 1. 建立构建基线与独立应用身份

- 使用开发分支 `codex/miniwatts-pro-analysis`，保留现有内部源目录、Xcode 工程和 scheme 名称。
- 修改主应用与小组件的 Debug/Release 显示名、bundle ID、entitlements 和共享数据路径。
- 同步应用文案、字符串目录、README、关于页、发行源脚本和 IPA 展示名称；仓库链接改为 `Ccat-Q/MiniWatts-Pro`，保留上游来源及许可证。
- 更新 `.github/workflows/build.yml`，增加开发分支 push 构建，保留 PR、手动运行及版本标签触发；仅 `v*` 标签允许发布 Release。
- 当前远端 Actions 已启用、工作流文件存在，但工作流尚未注册且无构建记录。通过配置后的开发分支构建验证工作流注册与执行，修复实际返回的失败，不预先断言原因。

影响范围：工程配置、签名关联、小组件共享读数、发行脚本和构建工作流。验收：Actions 首次成功生成 IPA；应用与小组件标识具有正确父子关系，App Group 一致，产物显示名正确，开发构建只上传产物。

### 2. 建立完整采样与长期历史存储

- 扩展样本上下文：真实可缺失电量、充电状态、观测断点；会话记录目标、设备型号、系统版本及最后观测时间。
- 删除最近 60 次会话限制和 1,500 点抽稀，不自动删除任何已记录样本；5 秒是历史保存间隔，不宣称保存全部每秒传感器原始数据。
- 使用带格式版本的独立会话文件和摘要索引。摘要包含能量、覆盖时长、温度统计及有效电量区间耗时，不携带完整样本数组；详情和导出按需加载样本。
- 先原子保存会话，再更新可重建索引；隔离损坏文件并提示，存储失败向用户反馈。加载与周期保存放在 UI 主线程之外。
- 强退后将未结束会话关闭到最后实际观测时刻，并标记中断；后台观测空洞不补值、不推断实际插拔时间。

技术判断：继续使用一个全历史 JSON 会让每次保存和启动随全部历史增长。按会话文件与摘要索引增加少量文件管理工作，避免全量编解码，并保留无依赖的现有技术路线；不采用继续抽稀或静默删除来降低存储成本。

影响范围：`ChargeSession`、`SessionStore`、`PowerMonitor`、历史详情和图表数据读取。验收：超过 60 次记录、超过 1,500 点、重启、缺口、损坏文件和写入失败的测试均在 Actions 通过；无静默覆盖和丢失。

### 3. 实现统一的预测与分析计算

把计算放在独立于 UI 和传感器探测的模型层；页面、摘要和报告使用相同口径，便于 Actions 执行确定性测试。

**剩余时间预测：**

- 以目标电量为终点，结合本次连续电量变化和同设备、同充电方式的历史；不由充电器额定功率或默认电池容量推算“实测”剩余时间。
- 历史按 5% 电量区间统计，仅使用有完整边界、连续观测且电量上升的区间；每段至少 3 个合格历史值后使用中位耗时。
- 本次趋势至少观察两次电量上升，使用近期完整变化的耗时；历史不足的区间可按本次趋势作粗略外推，明确预测依据和局限。
- 超过 10 秒的观测缺口、充电状态变化、电量下降及缺电量打断趋势。无可用依据时显示积累数据，未连接、暂停及观测中断时停止有效倒计时，达到目标时显示已达到目标。
- 不承诺未经实测的固定预测误差。用合成数据验证算法边界，真机记录用于后续评估实际误差和调整模型。

**单次与历史分析：**

- 支持 7 / 30 / 90 天、全部和自定义日期；按会话开始时间纳入完整会话，不在日期边界静默切割数据。
- 默认比较 20%–80%，允许调整；有线/无线分别比较。所选区间必须完整覆盖、观测覆盖率至少 90% 才能参与速度排名，其余记录保留复盘并说明原因。
- 计算区间用时、平均/峰值功率、输入与入电芯能量、电芯占比、系统负载与转换损耗、温度、系统热压力和各通道覆盖率。
- 平均功率由对应能量与有效测量时长计算；汇总电芯占比用成对能量之和相除；温度平均值按有效时长加权。
- 缺失值保持缺失，温度与热压力不直接证明降速原因；无线缺输入时不显示虚构输入能量或效率，适配器名称不作为可靠身份。

影响范围：新增预测/分析模型、`PowerMonitor` 的预测状态和会话摘要。验收：历史不足、尾段减速、状态切换、缺口、目标变化、部分覆盖和加权汇总测试通过；页面与报告不分别实现一套计算。

### 4. 接入分析页面与清理交互

- 电量页增加目标设置、预计剩余时间、估算依据与数据状态；更改目标后立即重新计算。
- 将原“历史”标签改为“分析”，提供总览/历史切换、日期筛选、可比电量区间选择、有线/无线结果及不可排名原因。
- 保留单次详情，补充统一分析指标与覆盖说明；图表在缺读数和观测空洞处断开。
- 屏幕绘图可按宽度抽点，持久化数据、计算和 CSV 使用完整样本。遵循现有局部观察结构，避免隐藏标签页或整页每秒重建。
- 提供存储占用、单条/日期范围/全部清理；先显示数量并确认，只删除已结束记录。刷新摘要、排名及存储占用，保留当前采样。

影响范围：`RootView`、电量页、历史页、单次详情、图表和设置页。验收：空历史、低覆盖、无传感器、加载/失败状态均有明确展示；自动化验证状态与筛选规则，真机另行检查滚动、布局及采样行为。

### 5. 生成完整 PDF 与两类 CSV

- 使用系统 PDF 绘制与分享能力，不增加第三方依赖。报告生成使用冻结的数据快照，注明导出时间、设备型号、系统/应用版本、目标、单位、时区及缺失数据；报告语言跟随应用。
- 单次 PDF 包含摘要、功率、电量和温度曲线，以及覆盖和估算说明。
- 区间 PDF 包含汇总、可比区间比较和分页会话摘要表，不自动附上所有会话的完整曲线。
- 摘要 CSV 一行对应一个会话；样本 CSV 标注所属会话、时间、读数、状态和观测断点，保留空值并正确转义引号、逗号及换行。
- 单次详情与分析总览分别提供导出入口；空范围禁用导出，大范围生成显示进度并可取消，失败提供原因及重试。
- 通过系统分享面板保存或分享；取消生成或分享都不修改历史。

影响范围：新增报告模型、PDF/CSV 生成、系统分享包装和导出 UI。验收：PDF 生成与分页、CSV 特殊字符/空值/单位/时间、不同语言、空范围和取消路径测试通过；页面、PDF 与 CSV 汇总一致。系统分享面板的实际交互需设备验证。

### 6. 完成 Actions 验证和交付

- 全部 Swift 编译、模型/存储/导出自动测试、iOS Release 构建和 IPA 验证由 GitHub Actions 执行。
- 本地仅检查 diff、字符串目录、plist、工程/工作流配置及脚本语法；不安装或调用本地 Swift/Xcode 进行编译。
- 逐个实施阶段推送开发分支，跟踪运行日志并修复失败；最终构建对应最后提交，所有要求的检查通过后再交付。
- 工作流校验 IPA 的主应用/扩展标识、显示名、版本和无签名分发要求，上传 `MiniWattsPro-unsigned.ipa` 与 dSYM。
- 同步 README、工程笔记、功能规范和相关 ADR；修正“差额全为热”及“数据永不离开设备”的旧文案。
- 提供最后提交、Actions 运行链接、IPA 下载位置、通过的测试及尚需真机验证的项目；不把构建成功等同于传感器准确或所有界面交互已验证。
